# Optimizer - Спецификация

## Суть задачи

Проблема: проигрываем на монетах которые не откатываются (или откатываются с другими процентовками).

Решение: отдельное приложение которое анализирует исторические данные и подбирает оптимальный порог `min_spike_move_pct` для каждой монеты индивидуально.

---

## Архитектура

**Два отдельных приложения с ОТДЕЛЬНЫМИ кодовыми базами:**

### 1. Prod Bot (текущий бот + минимальные доработки)

- Один бот торгует все монеты (как сейчас)
- `min_spike_move_pct` читается НЕ из config.toml, а из отдельных JSON файлов
- Для каждой монеты свой файл: `/thresholds/{SYMBOL}.json`
- Если файла нет или `enabled: false` → монета не торгуется
- Hot reload: следим за mtime файлов, обновляем только когда файл изменился (не при каждой генерации сигнала)
- Все остальные параметры (TP, SL, trailing, breakeven и т.д.) читаются из config.toml как сейчас

### 2. Optimizer (новое приложение)

- Строится на том же коде что и текущий Prod Bot
- Вся логика входа, генерации сигналов, TP/SL/trailing/breakeven - 1 в 1 как в прод боте
- Вместо отправки ордеров на биржу → симуляция
- Вместо live WebSocket → aggTrades из кэша + WebSocket дописывает новые
- Перебирает `min_spike_move_pct` для поиска оптимального значения
- Создаёт JSON файлы для прод бота

---

## Структура JSON файла порога

Путь: `/thresholds/{SYMBOL}.json`

```json
{
  "min_spike_move_pct": 0.8,
  "enabled": true,
  "pf": 1.82,
  "trades": 15,
  "updated_at": 1716300000
}
```

**Prod Bot читает только:** `min_spike_move_pct`, `enabled`

**Остальные поля (`pf`, `trades`, `updated_at`):** для дебага и понимания

## Поток работы Optimizer

```
[Старт]
    ↓
Читаем конфиг
    ↓
Получаем список монет (volume 24h фильтр - как в прод боте)
    ↓
Проверяем кэш на диске → берём данные которые подходят по времени
    ↓
Докачиваем недостающие aggTrades (REST API)
    ↓
Первичный бэктест по всем монетам → пишем JSON файлы
    ↓
Подключаем WebSocket aggTrades
    ↓
[Бесконечный цикл]
    ├── WebSocket → ring buffer (новые данные входят, старые удаляются)
    ├── Каждые N минут → пересчёт бэктеста → update JSON если порог изменился
    └── Периодически → дамп кэша на диск
```

---

## Rolling Window (плавающее окно)

- При старте скачиваем aggTrades за последние N часов (указывается в конфиге)
- WebSocket дописывает новые трейды
- Старые трейды удаляются (каждый новый трейд - убивает самый старый за пределами окна)
- Пример: окно 2 часа, обновление каждые 10 минут
  - При пересчёте берём 2 часа данных
  - 1ч 50мин из кэша + 10 мин новых из WebSocket

---

## Бэктест per coin

1. Перебор `min_spike_move_pct` от X до Y с шагом Z (всё из конфига)
2. Все остальные параметры - константы из конфига (как в прод боте)
3. Симуляция трейдов:
   - Вход по сигналу
   - Выход по TP (FULL, не partial) или SL
   - Логика TP/SL/trailing/breakeven - ровно как в прод боте
4. Метрики: Profit Factor, количество трейдов
5. Результат:
   - Если найден порог с `PF >= min_profit_factor` и `trades >= min_trades` → записываем лучший
   - Если нет подходящего порога → `enabled: false`

---

## Конфиг Optimizer

Конфиг файл 1-в-1 как у прод бота, но:
- Без API ключей
- Вместо `min_spike_move_pct` → отдельный блок `[optimizer]`
- Все остальные параметры (фильтры, TP/SL, механизмы) - точно такие же

```toml
# === Всё как в прод конфиге ===
[strategy]
min_volume_24h = 50_000_000
spike_multiplier = 3.0
# min_spike_move_pct - НЕТ ЗДЕСЬ
max_entry_distance_pct = 0.3
# ... остальные фильтры

[trading]
tp_pct = 0.5
sl_pct = 0.8
# ... все механизмы TP/SL/trailing/breakeven

# === Новый блок ===
[optimizer]
window_minutes = 120
refresh_interval_minutes = 10
min_spike_move_from = 0.2
min_spike_move_to = 2.0
min_spike_move_step = 0.2
min_profit_factor = 1.5
min_trades = 5
thresholds_dir = "./thresholds"
cache_dir = "./cache"
```

---

## Кэш aggTrades

- Формат: бинарный (bincode) - компактность и скорость, читаемость не нужна
- Один файл на монету
- При старте: проверяем кэш, берём только данные которые подходят по времени, остальное удаляем
- Периодически дампим на диск

---

## Симуляция

- Вся логика входа регулируется из конфиг файла (как в прод боте)
- Используем aggTrades - можем получить почти одинаковое поведение с live трейдером
- TP: при касании цены - сразу FULL (не partial)
- Slippage, точность исполнения и т.д. - как указано в конфиге

---

## Ключевые принципы

1. Optimizer и Prod Bot - ОТДЕЛЬНЫЕ кодовые базы
2. Optimizer строится на коде Prod Bot, адаптируется под симуляцию
3. Prod Bot получает минимальные доработки (читать пороги из JSON вместо config.toml)
4. Вся логика трейдинга в Optimizer - 1 в 1 как в Prod Bot (кроме min_spike_move_pct)
5. Заново ничего не пилим - дорабатываем/адаптируем существующий код
